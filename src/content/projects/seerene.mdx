<StorySection number="01" title="Three levels, one finding" id="levels">
  <p slot="problem">Seerene serves three user groups with different questions. Software architects dig deep into the code. Mid-level management (engineering and team leads) prepares their findings for managers. The C-Level (CXO, CTO, CIO) doesn't want to read technical reports but wants to steer the direction.</p>
  <p slot="decision">The platform connects the three levels in both directions. Each level has its own tool, and a finding travels up from the 3D software map through application details and rankings to the dashboard. Goals travel down from the C-Level to the development teams. Any dashboard widget leads back down to the code behind it.</p>

<StorySection number="02" title="The software map" id="map">
  <p slot="problem">Across thousands of files, outliers are hard to see in a list. The map existed only as a desktop "rich client", and the old renderer's colours were muddy. There was no user data yet, so I interviewed customer success and internal developers with the architect profile.</p>
  <p slot="decision">Files are buildings and folders are districts. Height, colour and area carry up to three KPIs, so outliers stand out at a glance. The map supports two jobs: identify outliers, then analyse their root cause. Selecting a point in the chart highlights the revisions and their buildings, and a click on a building opens the code unit inspector. A new renderer with exact colour scales replaced the old look.</p>
  <p slot="outcome">The map moved into the web platform and became the architect's main tool.</p>

<StorySection number="03" title="Making KPIs comparable" id="kpis">
  <p slot="problem">Putting different KPIs in relation to each other is key for managers. Customers were used to an expandable KPI list, but it served that need only indirectly.</p>
  <p slot="decision">The application details page compares two KPIs side by side, with a chart over time. Customer feedback added Code Changes as a third, fixed chart to spot critical commits. KPI and page descriptions add guidance. A ranking compares applications with each other.</p>
  <p slot="outcome">Managers get a comparison at a glance, and "Show on Map" leads each KPI back to the code.</p>

<StorySection number="04" title="Reporting upward" id="reporting">
  <p slot="problem">The map lost its state on every reload, and findings could not be passed on.</p>
  <p slot="decision">Saved Views started as that fix and became the bridge: a filtered map state can be placed on a dashboard as a widget. Dashboards collect scorecards, Top-5 rankings, saved views and targets, and are shared with colleagues. Executives read a result; one click on "Show on Map" takes anyone back down to the evidence.</p>
  <p slot="outcome">Mid-level management presents a finding in a form the C-Level can read without opening anything technical.</p>
